# Qmd

Qmd is a locally run Quick Markdown Viewer. It scans a target directory for Markdown files, starts a local HTTP server, and provides a web interface for browsing and reading those documents.

## Features

- Scans `.md` and `.markdown` files
- Displays Markdown documents in a tree-based sidebar
- Hides folders that do not contain Markdown files
- Supports filename search, light/dark themes, Markdown rendering, and code highlighting
- Binds to `127.0.0.1` for local document previewing

## Tech Stack

- Bun
- Vite
- TypeScript
- Svelte
- marked
- highlight.js
- DOMPurify

## Quickstart

Install dependencies:

```powershell
bun install
```

Start development mode:

```powershell
bun run dev
```

Development mode starts both servers:

- Vite frontend server: `http://127.0.0.1:5173`
- Bun backend server: `http://127.0.0.1:3000`

Build the UI and CLI binary:

```powershell
bun run build
```

Run the built CLI:

```powershell
.\bin\qmd.exe . --no-open
```

Open the viewer:

```text
http://127.0.0.1:3000
```

## CLI Usage

```text
qmd [directory] [options]
```

Examples:

```powershell
# Scan the current directory on the default port 3000
.\bin\qmd.exe

# Scan the docs directory
.\bin\qmd.exe .\docs

# Use a custom port and do not open the browser automatically
.\bin\qmd.exe .\docs --port 8080 --no-open

# Limit scan depth and ignore the drafts folder
.\bin\qmd.exe .\notes --depth 2 --ignore drafts
```

Options:

| Option | Description |
| --- | --- |
| `[directory]` | Directory to scan. Defaults to the current directory |
| `-p, --port <number>` | HTTP server port. Defaults to `3000` |
| `--no-open` | Do not open the browser on startup |
| `-d, --depth <number>` | Maximum recursive scan depth |
| `-i, --ignore <pattern>` | File or directory pattern to ignore. Repeatable |
| `-v, --version` | Show the version |
| `-h, --help` | Show help |

## Development

Common commands:

```powershell
bun run dev
bun test
bun run lint
bun run build
```

Scripts:

| Script | Description |
| --- | --- |
| `bun run dev` | Starts the Vite frontend and Bun backend together |
| `bun test` | Runs Bun tests |
| `bun run lint` | Runs Svelte and TypeScript checks |
| `bun run build:ui` | Builds the frontend into `dist/` |
| `bun run generate:assets` | Converts `dist/` into a static asset manifest for CLI embedding |
| `bun run build:cli` | Compiles the CLI binary into `bin/` |
| `bun run build` | Builds both the UI and CLI |

## Build Outputs

These directories are generated and ignored by `.gitignore`:

- `dist/`
- `bin/`
- `node_modules/`

`src/cli/assets.generated.ts` is generated by `bun run generate:assets`. It contains the static asset manifest used by the compiled CLI to serve the frontend UI.
